# Olist 商家运营行动与验证方案

## 方案状态

这是依据历史公开样本提出的运营方案，未上线、未随机分组、没有实测增量收益。原始数据不含完整入驻流程、客服触达、渠道费用和利润，下面的原因与动作需在取得真实业务数据后验证。

## 先确定谁可以被分析

成交商家按日期正常、90天观察窗完整、是否能映射到公开商家样本分别审计。未知覆盖不是未激活，未激活也不是已确认流失。运营对象名单只能在授权内部数据中使用，不在公开作品集中发布匿名ID或原始行。

## P0 核对数据和业务事实

分析人员核对负成交时滞、缺失来源、MQL与商家映射；与业务人员确认首次接触、签约和有效首单定义。初步核查目标约一个工作日，实际依数据访问情况调整。验收看异常是否可解释、分母是否一致、SQL与Python是否对账，不以“全部填满”代替正确。

## P1 可观测未激活商家试点

数据事实是合格可观测商家在指定90天内没有满足口径的订单。待验证假设包括签约后上架未完成、商品供给不足、入驻承接不足；公开数据不能判定哪个是真因。商家运营先核对上架记录、库存、触达与工单，再选择与证据匹配的支持动作。

拟做一次商家级随机对照试点，A组保持常规服务，B组增加已明确的激活支持，例如上架检查与一次针对性指导。不得把发券、加触达、改商品和改渠道同时混在一个处理组，以免结果无法解释。

试点需要新的内部事件日志和授权，不能把这批2017—2018历史未激活商家直接视为今天可联系的对象。

### 实验口径

- 随机单位：商家，名单去重；在渠道及入驻时间分层内随机，确保同一商家不跨组。
- 入组：真实业务中签约后仍未产生有效首单、具备服务条件的商家；异常日期与数据无法确认者暂不纳入。
- 核心指标：入组后固定30天内的有效首单商家数/全部随机入组商家数，按最初分组分析，不能只留下成功触达者。
- 中间指标：指导到位率、上架完成率、首单链路完成率。这些需要新增日志，现有公开表算不出来。
- 保护指标：取消/退款率、投诉率、单商家服务工时与成本；阈值由业务负责人依据真实基线预先确认。
- 时间：准备期后完整观察30天，再等订单状态成熟；不能用“做完一周”替代完整观察。最短周期受样本量和订单成熟周期约束。
- 样本量：先用真实基线首单率、业务认可的最小改善幅度和显著性/把握度计算；现有未激活样本量只支持方案设计，不保证有统计功效。

### 如何判断和复盘

在实验前冻结指标、样本量、观察期与分析规则。结果报告组间差异和置信区间，同时检查保护指标；不因某天看起来显著就提前停止或选择性汇报。

如果最终首单率提高且质量和成本可接受，再考虑扩大试点。若只有上架或点击等中间指标提高，首单率没有改善，不宣布成功：先查区间是否过宽、处理动作是否实际到位、订单状态是否成熟，再定位上架到首单的断点。若核心指标与中间指标均无改善，回查处理是否有作用及假设是否成立；若数据异常，先修数据，暂停业务解释。

## P2 已激活商家经营支持

按样本内90天商品GMV识别高贡献和其他已激活商家，了解库存、履约和服务需求。q75阈值只是当前样本的描述性分组，q70/q80检查用于判断建议是否依赖一个任意切点。历史高贡献不等于未来一定稳定，也不代表营销投入最优。

负责人角色是商家运营，分析人员提供群体诊断。先用小范围经营复盘验证需求，不向全部高贡献商家自动投放资源。验收可看商家订单、履约质量与服务成本；现有数据不完整支持退款、成本或真实经营维护效果，必须补业务记录。

## 渠道动作

付费、自然搜索和社交来源的成交与后续样本贡献存在差异；先查来源标记、覆盖、商家类型、月份构成和承接流程。缺少成本时只给“优先验证”顺序，不给“加预算/停投”的确定结论。
