运营优先级

P0 数据核验：先处理日期异常、来源缺失和映射缺口；没有可靠对象与口径，不能直接触达或调整预算。

P1 激活试点：对合格可观测未激活商家，先排查承接、上架与供给，再测试经营支持；这些原因是待验证假设。

P2 经营维护：了解高贡献商家和其他已激活商家的经营需求，同时核查贡献集中是否形成经营依赖，不把历史高GMV当成必然高收益。

验证方案尚未执行

拟在取得真实入驻与订单日志、确认试点资格后按商家随机分组，比较常规服务与新增激活支持。核心指标为固定时间内有效首单率；保护指标包括取消率、投诉率和服务成本。公开样本只用于提出方案，不能代替上线实验结果。

若中间指标改善但有效首单率不变，不能宣布成功；先检查样本量、执行到位率与首单链路，再判断是否继续。

第二案例 · 零售经营分析

从交易明细中识别陶瓷相关商品的经营结构

从公开英国零售交易数据中按陶瓷相关关键词形成可追溯子集，完成清洗、销售汇总与客户分层，并把结果呈现在 BI 看板中。

关键词审计记录22,427
有效交易记录21,655
商品 / 客户78 / 2,585

边界：这是历史公开零售数据中的“陶瓷相关关键词子集”，不是中国陶瓷行业市场份额，也不是 387 条拍卖成交数据。销售额另按 21,541 条严格销售记录汇总，为 GBP 450,066.19。

方法、复现与边界

把最容易算错的地方公开

统一分母与观察窗

每条完整观察MQL保留一行。未匹配商家在“样本内可观测贡献”中为0，但真实经营价值未知；商家运营表用空值保留未知。窗口为首次接触后 `[0, 90)`。

控制 JOIN 粒度

1,278 个订单包含多个商家。商品 GMV 在商家商品行上归属，订单数才按 order_id 去重，避免把整单金额重复分配。

双重验证

Python 生成 MQL 级价值表；SQLite 用 6 组独立查询重算总量和渠道结果。单元测试覆盖第 89/90 天、取消订单、成交前订单和重复键。

结论边界

462 个成交商家不在公开订单样本；缺少成本、利润和随机实验。可观测 GMV 不是 ROI、完整 LTV 或因果增量。
